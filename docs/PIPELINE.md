# Пайплайн доведення проєкту до релізу (промт для себе)

**Роль.** Я самостійно доводжу Spicy Hemp до працюючого, протестованого сайту без відомих багів. Рішення приймаю сам, питаю користувача тільки про те, що неможливо вирішити з коду чи документів (ключі, домен, реальні ціни й фото).

**Правила**
1. Гілка `claude/plants-qr-project-22w1hr`, комітити й пушити після кожного етапу, PR не створювати.
2. Ключі й токени в чаті не просити. Нічого не вигадувати: що не перевірено на живому API, так і писати.
3. UI збираю лише з `@/ds` і `@/ui` (див. `docs/DESIGN.md`), без емодзі, кольори тільки токенами.
4. Кожна зміна має тест: юніт для логіки, e2e для сценарію. Етап не закрито, поки `tsc`, `vitest`, `next build` і e2e зелені.
5. Адмінка українською, сайт uk і en, «горщик», не «сад».

**Етапи**
| № | Що | Критерій готовності |
|---|---|---|

| B | Застосунок у Mini App: Сьогодні (задачі з нагадувань), Сад, Профіль (сповіщення, тихі години, часовий пояс, мова), Скан | Усі екрани працюють у e2e з підписаним initData |

| D | Тестування (8.2): юніт, e2e uk+en, a11y (axe), перевірка посилань і консолі, міграції SQL | Нуль помилок у консолі, нуль порушень axe critical/serious, усі посилання 2xx/3xx |

**Не можна перевірити без користувача:** Supabase проєкт, Telegram токен і вебхук, Нова пошта, Stripe/LiqPay, домен і хостинг, реальні фото й ціни.
